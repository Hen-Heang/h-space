# UI review

Review a frontend change in this order:

1. Confirm the requested flow and inspect direct page/component dependencies.
2. Check hierarchy, spacing, typography, states, responsive layout, and reuse of existing primitives.
3. Check keyboard behavior, focus visibility, labels, contrast, image alternatives, and touch targets.
4. Check that client/server boundaries, API usage, auth behavior, and data ownership remain intact.
5. Report findings with a file location, user impact, and a concrete recommendation.

Do not redesign unrelated screens or treat a successful build as proof of visual correctness.
