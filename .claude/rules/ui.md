# UI rule

- Preserve the existing product language, visual system, and interaction patterns.
- Inspect the target page and its direct components before changing shared UI.
- Reuse existing components, tokens, icons, typography, and loading/error states.
- Design mobile-first and check at approximately 375px, 768px, 1024px, and 1440px.
- Keep keyboard navigation, visible focus, semantic labels, accessible names, and readable contrast.
- Keep touch targets usable and prevent accidental horizontal overflow.
- Treat loading, empty, error, unauthorized, and populated states as part of the UI.
- Keep animation subtle and useful. Do not add visual noise, broad redesigns, or dependencies for simple effects.
- Do not change API contracts, authentication, authorization, or database behavior during a UI-only task.
