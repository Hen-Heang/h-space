# Base rule

- Read existing instructions and the smallest relevant code surface first.
- Preserve public behavior, data contracts, authorization, and local conventions.
- Prefer a focused patch over a broad refactor.
- Reuse existing components, helpers, and types before creating new ones.
- Never expose credentials, tokens, private keys, or real environment values.
- Never commit, push, deploy, migrate, or write a database without explicit direction.
- Keep facts in project context documents instead of inventing assumptions.
